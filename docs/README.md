# docs 文档索引与维护规范

本目录维护项目**常驻增量文档**，避免为每个迭代新建零散文件、扰乱 git 历史。

## 常驻文档

| 文件 | 内容 | 更新方式 |
|---|---|---|
| `CHANGELOG.md` | 版本更新记录（功能/修复/优化/技术演进） | 每次发版在**顶部新增章节**，不新建文件 |
| `technical-reference.md` | 实现细节参考（工具/数据模型/构建） | 涉及实现变更时增量维护 |

## 归档

`archive/` 存放已完成的**历史设计/规划文档**（不再更新）：

- `refactoring-plan.md` — 架构重构历程（v2.x）
- `update-plan.md` — 分期更新计划
- `account-page-redesign.md` / `theme-color-redesign.md` / `image-storage-redesign.md` — 页面/主题/存储设计稿
- `PR-3.0.80.md` — 3.0.80 发版 PR 说明（一次性，可作格式参考）

## 维护规范（为什么这样）

1. **不新建「一次性」文档**：PR 说明、代码复查结论等**过程性内容**不单独成文件——写入 `CHANGELOG.md` 或提交说明即可（GitHub PR 描述可直接从 CHANGELOG 对应版本章节复制）。
2. **版本更新只动 `CHANGELOG.md`**：每次版本迭代在文件顶部加章节（增量、追加），git 记录是「一个文件反复更新」，而非每次新增一个带版本号的文件。
3. **README 不膨胀**：README（项目根）面向用户，只保留概述、快速开始、功能与链接；细节变更一律进 CHANGELOG。
4. 设计/方案类内容若要长期留存，先评估是否并入 `technical-reference.md`；确属历史归档的放入 `archive/` 并停止更新。

## 约定

- 版本号与 git 提交号同步（3.0.x，versionCode = 主×10000+次×1000+补丁）
- 中英文 UI 文案须资源化；文档以中文为主
