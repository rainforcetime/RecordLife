## P1 逻辑缺陷（必须修）

### 1. 评论区增删后面板列表可能不刷新
- **现象**：在「追加想法」面板添加/删除一条后，列表可能不更新（新评论不出现、删除项不移除），关闭重开才正确。
- **根因（引用链实锤）**：
  1. `RecordModel.buildTimelineData`（RecordModel.ets:97）`dayMap.get(day)!.push(record)`——时间线内 record 与 `viewModel.records` 中为**同一对象引用**（未拷贝）；
  2. `NowViewModel.addComment` 对 record.comments 做**原地 push**；
  3. `NowPage.syncCommentTarget`（NowPage.ets:622-628）`commentTarget = viewModel.getRecordById(id)`——返回的仍是**同一引用**；
  4. ArkUI `@State` 赋值**相同引用**时判定无变化，不触发 UI 重建 → 列表不刷新。
- **修复方向**：`syncCommentTarget` 赋**新引用**（浅拷贝 + comments 新数组），例如
  `this.commentTarget = { ...fresh, comments: fresh.comments ? [...fresh.comments] : undefined }`。
- **影响面**：需求 3 核心交互；需修复 + 真机复测（新增后立即显示、删除后立即移除、清空后回空态）。

## P2 体验/边界问题（建议处理）

### 2. 编辑未改动也标记「已编辑」
- `updateRecord` 无条件写 `updatedAt = Date.now()`——打开编辑框点保存（内容未变）也会让卡片显示「编辑于」。
- **建议**：保存时若 content/mood/tags/图片与旧值均相同，不更新 `updatedAt`（需做一次 diff 判断）。

### 3. 评论输入框清空机制未确认
- 添加后代码置 `commentText = ''`，但 `TextArea({ text: this.commentText })` 为单向传值；若该参数仅作初始值（非受控），输入框可能残留上一条文字。
- **建议**：改用 `$$` 双向绑定（`$$this.commentText`）或真机验证；若残留则切换受控方式。

### 4. 隐私遮罩覆盖范围与「工具栏」边界
- 当前遮罩是 NowPage 根 Stack 内全屏盖层，**顶部标题/筛选/视图切换也一并被模糊挡住**，隐私模式下无法切换时间线/日历、无法搜索。
- 已按你选的「整页记录区域模糊」实现；若希望保留工具栏可操作，需把遮罩下移只盖列表区（结构调整）。**请确认预期**。

### 5. 评论删除无二次确认
- 删除评论直接 splice，不走撤销流程，误触不可恢复。
- **建议**：与记录删除一致加确认弹窗，或轻量 Toast 撤销；至少真机确认误触频率可接受。

## P3 优化点（可选）

6. **跨年编辑时间**：`formatEditedAt` 同日只显时分、跨日补 M/D，跨年未含年份（如去年编辑显示 `12/31 10:00` 无年份）——轻微，可接受或补年份。
7. **卡片操作条密度**：置顶/分享/💬/编辑/删除 5 项 + space 24，窄屏/长文案记录下可能拥挤——真机观察，必要时减小间距或收进「更多」。
8. **隐私模糊性能**：`backdropBlur(24)` 整层盖在列表上，超大记录量时滚动/开关可能有性能开销——真机观察，必要时降模糊半径或只对静态快照生效。
9. **评论面板数据快照**：打开面板后若该记录在别处被改（删除等），面板不感知——单机低频操作，风险低，可接受。
10. **图标/符号资源化**：`💬 🗑 ✕` 为 emoji/字符（非语言文本，可接受）；若将来换主题色需图标可考虑 `sys.symbol`/资源化（低优先）。
